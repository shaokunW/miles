# Factorio — automation and changing responsibility

## Reference and evidence

The developer presents Factorio around factories, infrastructure, research, and automated production. Those features support using it as a reference for automation-oriented play. The progression proposed below is Miles's analytical application, not a transcript of a specific tutorial or player study. [CASE-06](../../references/sources.md#case-06)

## Miles interpretation

A useful automation question is what responsibility moves to the player after a repeated operation becomes automatic. Agency can remain in arranging, prioritizing, diagnosing, and expanding systems.

Candidate chain: operate a process → recognize a limitation → gain automation → inspect its consequences → choose the next improvement. Its suitability depends on the intended audience and fantasy.

## Original transfer proposal

For a fictional small restaurant game, automate carrying clean plates only after players understand where plates are used. Keep staffing and capacity as visible decisions. Show which stage is limiting service using the same state language the player learned manually.

Make the first automation's benefit perceptible in the restaurant. Avoid adding production graphs or multiple resource chains merely because an industrial reference uses systemic complexity.

## Boundary and test

An audience seeking tactile craft work may value direct operation. Another audience may enjoy delegation. Confirm which role the project promises before removing a repeated action.

Observe what players do after delegation. Ask them to identify the new constraint and select an improvement. Repeatedly waiting without an intention may reveal missing agency; happily watching can be valid if relaxed observation is an explicit goal.

**Persistent knowledge:** accepted automation principles require a named system and release scope. A single staff upgrade does not define the whole game's long-term interaction model.
